# Оптимізація PocketBridge під LG Optimus One P500

## Цільова платформа

- LG Optimus One P500;
- 320×480;
- Android 2.3.3 / CyanogenMod 7.2;
- ARMv6;
- старий системний WebView;
- локальна Wi-Fi мережа.

## Реалізована архітектура

### 1. Гібридний клієнт

Основний Android-клієнт має три рівні:

1. **P500 Ultra Lite Web UI** — щоденний режим із мінімальним DOM.
2. **Native Remote** — резервний нативний пульт без WebView.
3. **Full Web UI** — розширені інструменти, які відкриваються лише за потреби.

### 2. Ultra Lite UI

`/p500/` містить лише:

- компактний статус CPU/RAM/активного процесу;
- до 6 кнопок поточного профілю;
- тачпад;
- клавіатурні скорочення та введення тексту;
- швидкий перехід до повного UI.

Великі списки вікон, аудіосесій, файлів і буфера не присутні в DOM Ultra Lite сторінки.

### 3. Компактний API

`GET /api/p500/bootstrap` повертає скорочені профілі, дозволи й інтервали.

`GET /api/p500/status` повертає короткі поля:

```json
{"o":1,"c":18,"r":36,"u":7200,"p":"chrome.exe","w":"PocketBridge","e":1}
```

Медіадані запитуються не кожного циклу, а періодично або після явного оновлення.

### 4. Адаптивне опитування

- після натискання: приблизно 3 секунди;
- активна панель: за замовчуванням 8 секунд;
- інші вкладки або простій: 20 секунд;
- помилки: 5 → 10 → 20 → 30 секунд;
- прихована сторінка: 30 секунд.

Одночасно працює лише один status-запит.

### 5. Тачпад

Рух пальця накопичується та надсилається пакетами. За замовчуванням інтервал дорівнює 80 мс. Новий запит не створюється, поки попередній не завершився.

### 6. Мережа й кеш

- GZip middleware для відповідей від 500 байтів;
- `p500.v110.min.css` і `p500.v110.min.js` кешуються як immutable;
- API має `no-store`;
- HTML перевіряється при запуску;
- Android WebView використовує кеш мережевих ресурсів у Lite-режимі.

### 7. WebView

У Lite-режимі:

- JavaScript увімкнений;
- DOM Storage залишається лише для токена й вибраного профілю;
- Database/Web SQL вимкнено;
- файловий доступ вимкнено;
- zoom, збереження форм і паролів вимкнено;
- зовнішні host/port блокуються;
- `addJavascriptInterface` відсутній.

## Параметри конфігурації

```json
{
  "performance_mode": "p500",
  "p500_status_refresh_seconds": 8,
  "p500_idle_refresh_seconds": 20,
  "p500_touch_interval_ms": 45,
  "p500_screen_quality": 32,
  "p500_screen_max_width": 320,
  "p500_max_buttons": 6
}
```

Старий `config.json` мігрується автоматично.

## Практичні налаштування для P500

- залишити Ultra Lite UI увімкненим;
- головний профіль обмежити шістьма найчастішими командами;
- використовувати Native Remote при проблемах WebView;
- перегляд екрана відкривати лише за потреби;
- JPEG: 320 px і 25–35%;
- вимкнути звук зворотного зв’язку, якщо важлива максимальна швидкість;
- затемнення встановити на 30–60 секунд;
- не відкривати одночасно повний UI і Ultra Lite в різних вкладках.

## Що ще потребує реальної перевірки

- час першого запуску на фізичному P500;
- RAM системного WebView;
- фактична затримка команд у домашній Wi-Fi мережі;
- плавність тачпада при 60/80/100 мс;
- поведінка після тривалого простою на зарядці;
- відновлення після втрати Wi-Fi;
- debug і release APK на CyanogenMod 7.2.

## Native Core у v1.2.0

Починаючи з v1.2.0, рекомендований режим P500 не створює WebView під час звичайної роботи. Профілі, кнопки, тачпад, клавіатура й статус реалізовані в `NativeCoreActivity`. WebView завантажується лише після відкриття розширених інструментів.

Ключові параметри:

- один bootstrap-запит із початковим статусом;
- кеш профілів окремо для кожного ПК;
- обмежена черга команд;
- окрема обмежена черга миші;
- тачпад 60–200 мс між пакетами;
- polling 8/20 секунд із backoff 5/10/20/30 секунд;
- максимум шість кнопок активного профілю.
