# PocketBridge v1.9.1 — повне відлагодження функцій

## Обсяг аудиту

Перевірено сервер FastAPI, конфігурацію та міграції, авторизацію і парування, WebSocket/HTTP input, Windows input, макроси, панелі YouTube/VLC/PowerPoint, Smart Profiles, моніторинг, Wake-on-LAN diagnostics, віддалений екран, буфер обміну, Android Share, файловий менеджер, backup/restore, усі вебінтерфейси, Android Native Core для LG P500 і Redmi Note 9 Pro, а також GitHub Actions.

## Усунені дефекти

### Тачпад і realtime input

- HTTP fallback тепер відправляє залишковий рух перед `drag_end`.
- Повторення критичного `drag_end` обмежене чотирма спробами: кнопка миші не залишається затиснутою, але клієнт також не створює нескінченний потік запитів.
- WebSocket-черга об’єднує лише пакети руху. Кліки, клавіші та межі drag не витісняються старими рухами.
- Коли bounded queue заповнена критичними подіями, Android переходить на HTTP fallback замість втрати команди.
- Сервер гарантовано відпускає ліву кнопку після disconnect і після ввімкнення runtime pause.
- `NativeRequestQueue` перехоплює непередбачені винятки команд і повертає контрольовану помилку в UI.

### Віддалений екран

- Windows-процес вмикає DPI awareness до створення UI/захоплення екрана.
- Координати кліку враховують `object-fit`, letterbox, масштабування Windows і точні краї кадру.
- Android фіксує monitor ID, ширину та висоту саме того кадру, по якому виконується клік.
- Відповідь від попереднього монітора відкидається після перемикання екрана.
- Callback не змінює Activity після `pause`/`destroy`.
- `OutOfMemoryError` під час JPEG-декодування обробляється без аварійного завершення APK.
- Звичайні JSON-відповіді обмежені 512 КіБ, а кадр екрана має окремий контрольований ліміт 2 МіБ. Це усуває помилкове відхилення якісного кадру Redmi та зберігає захист пам’яті LG P500.
- Серверний capture gate має timeout і не може назавжди заблокувати наступне захоплення.

### Файловий менеджер

- `SafeFileStore` повторно перевіряє кінцевий шлях безпосередньо перед атомарним commit.
- Паралельні upload-запити не можуть зарезервувати один і той самий кінцевий файл.
- `rename_if_exists` створює безпечні імена `name (1).ext`, не перезаписуючи попередній файл.
- Upload використовує тимчасовий `.uploading`, `fsync` та атомарну заміну.
- Android download використовує `.part`, перевіряє очікуваний розмір, видаляє неповний файл і запускає MediaScanner.
- Upload/download мають ліміт 100 МіБ на стороні Android; сервер додатково застосовує власний налаштований ліміт.
- Імена з traversal, symlink, Windows ADS, керівними символами та `CON/PRN/AUX/NUL/COM1…/LPT1…` відхиляються або безпечно нормалізуються.
- Одноразовий download ticket споживається лише один раз і містить очікуваний розмір.
- Розрив клієнта під час upload повертає контрольований HTTP 499 та очищає тимчасовий файл.

### Backup і restore

- Архів спочатку створюється як `.creating`, перевіряється через ZIP/CRC і лише потім атомарно публікується.
- Пошкоджений ZIP повертає `BackupError`, а не необроблений виняток бібліотеки.
- Restore перевіряє дубльовані ZIP entries, граничні розміри, traversal, ADS і небезпечні shared-шляхи до зміни конфігурації.
- Shared-файли спочатку готуються у staging-каталозі.
- Під час помилки commit відновлюються попередні shared-файли та точні байти старого `config.json`.
- Конфігурація записується останньою, тому напіввідновлений стан не публікується як успішний.

### Wake-on-LAN, Windows і моніторинг

- Парсер `powercfg /a` не вважає S3 доступним, коли `Standby (S3)` згаданий лише у секції unavailable.
- PowerShell запускається з UTF-8, помилки команд відображаються у діагностиці.
- `wake_armed` звіряється з реальними Ethernet-адаптерами, а не з будь-яким рядком Realtek.
- Shutdown/restart перевіряють код запуску; monitor-off використовує `SendMessageTimeoutW`; закриття вікна перевіряє `PostMessageW`.
- System Monitor повертає часткові показники та список помилок, навіть коли окремий лічильник `psutil` недоступний.

### Сервер, конфігурація та UI

- Кількість профілів узгоджена до 12 у конфігурації, API, редакторі й Android bootstrap.
- `open_p500.bat` використовує Python із `.venv` і відкриває Lite UI з актуальним токеном.
- `X-Request-ID` приймається лише у безпечному форматі; довільні пробіли/керівні символи замінюються згенерованим ID.
- Recovery конфігурації пропускає новішу, але семантично пошкоджену резервну копію.
- Full UI коректно показує недоступні інструменти замість помилкового переходу на іншу сторінку.
- Додано відтворювану локальну перевірку `run_full_check.bat` і `scripts/validate_release.py`.
